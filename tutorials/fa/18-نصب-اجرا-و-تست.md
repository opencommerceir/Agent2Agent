# ۱۸. نصب، اجرا و تست پروژه — گام‌به‌گام

این فایل کاملاً عملی است. اگر می‌خواهید این پروژه را روی سیستم خودتان بالا بیاورید و دموی زنده را ببینید، همین‌جا شروع کنید.

## پیش‌نیازها

- PHP 8.2 یا بالاتر
- Composer
- Node.js و npm (برای ساخت فایل‌های فرانت‌اند پنل مدیریت و دمو)
- MySQL (اختیاری برای توسعه — تست‌ها از SQLite در حافظه استفاده می‌کنند)

## گام ۱ — نصب وابستگی‌ها

```powershell
composer install
```

این دستور همه‌ی پکیج‌های PHP از جمله `barryvdh/laravel-dompdf` (برای خروجی PDF گزارش‌ها) را نصب می‌کند.

SDK رسمی PHP هم وابستگی‌های خودش را دارد:

```powershell
cd packages/opencommerce-sdk
composer install
cd ../..
```

فایل‌های فرانت‌اند (Tailwind، Alpine.js، Chart.js — که پنل مدیریت و صفحه‌ی دمو به آن‌ها نیاز دارند):

```powershell
npm install
npm run build
```

> نکته: تست‌ها هرگز به این فایل‌های ساخته‌شده نیاز ندارند (`withoutVite()` در تست‌ها استفاده می‌شود) — اگر فقط می‌خواهید تست بزنید، این مرحله لازم نیست.

## گام ۲ — راه‌اندازی پایگاه‌داده

```powershell
php artisan migrate
php artisan db:seed
```

دستور `db:seed`، Seederهای قابلیت هر ماژول (Demo، Commerce، CRM، Finance، Workflows، Loyalty، Reporting، Shipping، Notifications، Analytics) را اجرا می‌کند و یک کاربر پیش‌فرض پنل مدیریت هم می‌سازد:

```
ایمیل: admin@opencommerce.test
رمز:   password
```

⚠️ حتماً قبل از هر استقرار واقعی (Production)، این کاربر پیش‌فرض را تغییر دهید یا حذف کنید.

برای این‌که لینک‌های فایل خروجی (مثل خروجی CSV/PDF گزارش‌ها) درست کار کنند:

```powershell
php artisan storage:link
```

## گام ۳ — اجرای مجموعه‌ی تست

```powershell
php artisan test
```

این باید حدود ۱۱۰۲ تست را با موفقیت اجرا کند (بدون هیچ خطا). برای تست SDK جدا:

```powershell
cd packages/opencommerce-sdk
vendor/bin/phpunit tests
cd ../..
```

## گام ۴ — بالا آوردن سرور

```powershell
php artisan serve --port=8000
```

حالا این آدرس‌ها در دسترس‌اند:

| آدرس | چیست |
|---|---|
| `http://127.0.0.1:8000/login` | ورود به پنل مدیریت (با کاربر پیش‌فرض بالا) |
| `http://127.0.0.1:8000/mcp/v1/*` | دروازه‌ی MCP نسخه‌ی ۱ |
| `http://127.0.0.1:8000/mcp/v2/*` | دروازه‌ی MCP نسخه‌ی ۲ |
| `http://127.0.0.1:8000/showcase` | دموی زنده (نیاز به Seed جداگانه — گام بعد) |

## گام ۵ — راه‌اندازی و اجرای دموی زنده Showcase

دموی زنده به داده‌ی مخصوص خودش نیاز دارد که به‌صورت پیش‌فرض Seed نمی‌شود:

```powershell
php artisan db:seed --class=DemoShowcaseSeeder
```

یا اگر دوباره می‌خواهید داده را از صفر بسازید (مثلاً بین دو بار دموی زنده):

```powershell
php artisan demo:reset
```

حالا به آدرس زیر بروید:

```
http://127.0.0.1:8000/showcase
```

- یک پرسونا (CEO/Sales/Support/Finance) انتخاب کنید.
- یکی از «اهداف پیشنهادی» را کلیک کنید یا خودتان یک جمله بنویسید (مثلاً «فروش این هفته رو ۱۵٪ افزایش بده»).
- منتظر بمانید تا چرخه‌ی «فکرکردن → برنامه‌ریزی → اجرا → بازتاب» زنده رندر شود.
- تب‌های پنل کناری (محصولات/سفارش‌ها/KPI) را ببینید که با داده‌ی واقعی به‌روزرسانی می‌شوند.
- روی دکمه‌ی 🕘 کلیک کنید تا تاریخچه‌ی گفتگوهای قبلی را ببینید.

### اگر می‌خواهید از یک مدل هوش مصنوعی واقعی (رایگان) استفاده کنید

در فایل `.env` این‌ها را تنظیم کنید:

```env
LLM_PROVIDER=openrouter
OPENROUTER_API_KEY=<کلید شما از openrouter.ai>
OPENROUTER_MODEL=meta-llama/llama-3.1-405b-instruct:free
```

بعد در صفحه‌ی دمو، کلید «🧠 استفاده از هوش مصنوعی واقعی» را روشن کنید. اگر کلید تنظیم نشده باشد، هیچ اتفاق بدی نمی‌افتد — سیستم به‌آرامی به Planner قطعی (Deterministic) برمی‌گردد.

### اگر می‌خواهید دموی زنده را با یک رمز عبور محافظت کنید

```env
SHOWCASE_PASSCODE=یک-رمز-دلخواه
```

اگر این را خالی بگذارید، هرکسی که آدرس `/showcase` را دارد می‌تواند مستقیم وارد شود.

## کارهای زمان‌بندی‌شده (Scheduled Commands)

پروژه چند دستور Artisan دارد که در استقرار واقعی باید هر دقیقه از طریق Cron واقعی صدا زده شوند (`* * * * * php artisan schedule:run`)؛ برای تست دستی می‌توانید هرکدام را مستقیم اجرا کنید:

```powershell
php artisan loyalty:expire-points           # روزانه، ساعت ۰۲:۰۰ — انقضای امتیاز وفاداری
php artisan commerce:check-abandoned-carts  # ساعتی — تشخیص سبد رهاشده
php artisan analytics:generate-snapshot     # روزانه، ساعت ۰۱:۰۰ — اسنپ‌شات تحلیلی
php artisan cache:warm                      # روزانه، ساعت ۰۰:۰۰ — گرم‌کردن کش
php artisan subscription:process-due        # روزانه، ساعت ۰۰:۰۰ — پردازش اشتراک‌های سررسیدشده
php artisan schedule:list                   # تأیید این‌که همه ثبت شده‌اند
```

## آزمایش دستی یک قابلیت MCP با curl

اول یک توکن Agent واقعی لازم دارید (روش ساخت آن در `packages/opencommerce-sdk/README.md`، بخش Quick Start توضیح داده شده). بعد:

```bash
curl -X POST http://127.0.0.1:8000/mcp/v1/execute \
  -H "Authorization: Bearer <agent-token>" \
  -H "Content-Type: application/json" \
  -d '{"capability":"demo.tools.echo","input":{"message":"سلام"}}' -i
```

برای نسخه‌ی v2، فقط `v1` را با `v2` عوض کنید — شکل پاسخ فرق می‌کند (`result`/`metadata` به‌جای `data`/`meta`) ولی رفتار یکسان است.

## ابزارهای عملکردی (اختیاری)

```powershell
php artisan performance:benchmark           # زمان‌سنجی جست‌وجوی محصول + محاسبه‌ی KPI
php artisan performance:check-lazy-loading  # بررسی الگوهای N+1 احتمالی
```

و صفحه‌ی `/dashboard/performance` (بعد از ورود به پنل مدیریت) آمار عملکرد پلتفرم را نشان می‌دهد.

## جمع‌بندی چک‌لیست سریع

```
✅ composer install (+ داخل packages/opencommerce-sdk)
✅ npm install && npm run build
✅ php artisan migrate && php artisan db:seed
✅ php artisan storage:link
✅ php artisan test  (باید ۱۱۰۲ تست سبز شود)
✅ php artisan serve --port=8000
✅ php artisan db:seed --class=DemoShowcaseSeeder
✅ باز کردن http://127.0.0.1:8000/showcase
```

در فایل آخر، نگاهی صادقانه به بدهی فنی شناخته‌شده‌ی پروژه و مسیر پیشنهادی آینده می‌اندازیم.
