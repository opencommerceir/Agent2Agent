# ۹. هوش مصنوعی، LLM و عامل‌های هوشمند

تا اینجا همه‌چیز درباره‌ی مهندسی نرم‌افزار «کلاسیک» بود. از اینجا وارد بخشی می‌شویم که این پروژه را از یک فروشگاه معمولی متمایز می‌کند: فاز ۶، هوش مصنوعی عامل‌محور. این فصل واژه‌های پایه را باز می‌کند؛ فصل بعد وارد جزئیات پروتکل MCP می‌شود.

## مدل زبانی بزرگ (LLM — Large Language Model)

**تعریف ساده:** یک مدل هوش مصنوعی که با خواندن مقدار عظیمی متن آموزش دیده تا بتواند متن بعدی را پیش‌بینی کند — و از این توانایی ساده، چیزهای شگفت‌انگیزی مثل پاسخ‌دادن به سؤال، نوشتن کد، یا خلاصه‌کردن متن بیرون می‌آید. مثال‌ها: GPT (از OpenAI)، Claude (از Anthropic)، مدل‌های متن‌باز روی OpenRouter.

**چرا مهم است:** LLM چیزی است که به این پلتفرم اجازه می‌دهد یک هدف متنی و مبهم («فروش این هفته را بیشتر کن») را به یک برنامه‌ی اجرایی مشخص («این ۴ قابلیت را با این ورودی‌ها اجرا کن») تبدیل کند.

📍 **در این پروژه:** `LLMClientInterface` یک قرارداد مشترک برای صحبت با هر LLM است؛ سه پیاده‌سازی واقعی دارد: OpenAI، Claude، و OpenRouter (سری اصلی، فایل ۱۳ و ۱۵).

## Prompt (پرامپت) و مهندسی پرامپت (Prompt Engineering)

**تعریف ساده:** «Prompt» متنی است که به یک LLM می‌دهید تا یک پاسخ خاص از آن بگیرید. «مهندسی پرامپت» یعنی هنر/فن نوشتن این متن به‌شکلی که پاسخ قابل‌اعتماد، دقیق و در فرمت درست باشد.

**چرا مهم است:** یک LLM هیچ حافظه‌ای از پروژه‌ی شما ندارد — هرچه لازم دارد بداند (چه قابلیت‌هایی وجود دارند، چه فرمتی باید برگرداند) باید هر بار در همان Prompt به آن گفته شود.

📍 **در این پروژه:** `PlanningPromptTemplate` دقیقاً یک سازنده‌ی Prompt است — فهرست کامل قابلیت‌های واقعی پلتفرم را در متن Prompt می‌گنجاند تا LLM بداند دقیقاً چه ابزارهایی در دسترس دارد.

## توکن و پنجره‌ی زمینه (Token / Context Window)

**تعریف ساده:** LLMها متن را به قطعات کوچک به نام «توکن» می‌شکنند (تقریباً هر توکن چند حرف است). «پنجره‌ی زمینه» یعنی حداکثر تعداد توکنی که یک مدل می‌تواند هم‌زمان «ببیند» — هم Prompt ورودی و هم پاسخ خروجی.

**چرا مهم است:** هرچه Prompt طولانی‌تر، هم هزینه‌ی بیشتر (اغلب سرویس‌ها بر اساس تعداد توکن قیمت می‌گذارند) و هم سرعت پایین‌تر — و اگر از پنجره‌ی زمینه رد شود، اصلاً کار نمی‌کند.

📍 **در این پروژه:** یک یافته‌ی واقعی و مستندشده: وقتی این پلتفرم لیست کامل ۱۲۷ قابلیت را (حدود ۲۰٬۷۰۰ کاراکتر) در هر Prompt می‌گنجاند، این حجم واقعاً روی سرعت پاسخ مدل‌های رایگان اثر منفی دارد — این یک یافته‌ی زنده و اندازه‌گیری‌شده است، نه یک حدس (`HANDOFF.md` §۷.۳۵)، و کاهش این حجم یک بهبود واقعی مسیر آینده است.

## فراخوانی ابزار (Tool Calling / Function Calling)

**تعریف ساده:** توانایی یک LLM برای این‌که به‌جای فقط «نوشتن متن»، بگوید «می‌خواهم این تابع خاص را با این ورودی‌های خاص صدا بزنم» — و بعد سیستم شما واقعاً آن تابع را اجرا می‌کند و نتیجه را به مدل برمی‌گرداند.

**چرا مهم است:** این دقیقاً همان چیزی است که یک LLM را از «چیزی که فقط متن تولید می‌کند» به «چیزی که واقعاً می‌تواند در دنیای واقعی کاری انجام دهد» تبدیل می‌کند.

📍 **در این پروژه:** هر «قابلیت» (Capability) دقیقاً همان «ابزار» قابل‌فراخوانی است — فصل بعد این را کامل باز می‌کند.

## عامل هوشمند (AI Agent)

**تعریف ساده:** یک سیستم که از یک LLM برای **تصمیم‌گیری** استفاده می‌کند، نه فقط تولید متن — یک هدف می‌گیرد، خودش تصمیم می‌گیرد چه ابزارهایی را به چه ترتیبی صدا بزند، نتیجه را می‌بیند، و در صورت نیاز مسیرش را عوض می‌کند.

**چرا مهم است:** تفاوت اصلی «چت‌بات ساده» با «Agent» دقیقاً همین است — چت‌بات فقط جواب می‌دهد؛ Agent واقعاً **کاری انجام می‌دهد**.

📍 **در این پروژه:** «Agent Orchestrator» (فاز ۶ کامل، سری اصلی فایل‌های ۱۲ تا ۱۵) دقیقاً همین چرخه را پیاده می‌کند: هدف → برنامه‌ریزی (Plan) → اجرا (Execute) → یادگیری از نتیجه.

## Fallback (بازگشت به مسیر امن)

**تعریف ساده:** یک استراتژی که اگر مسیر «هوشمند» (تماس با LLM واقعی) به هر دلیلی شکست بخورد (اینترنت قطع، کلید نامعتبر، Timeout)، خودکار به یک مسیر ساده‌تر و همیشه-کارکن برگردد، به‌جای این‌که کل درخواست با خطا شکست بخورد.

**چرا مهم است:** یک سرویس بیرونی (مثل یک API هوش مصنوعی) هیچ‌وقت ۱۰۰٪ قابل‌اعتماد نیست — یک سیستم جدی باید همیشه یک نقشه‌ی «ب» داشته باشد.

📍 **در این پروژه:** این یکی از قوی‌ترین و پرتکرارترین اصول این پلتفرم است — `LLMPlanner` اگر شکست بخورد، خودکار به `DeterministicPlanner` (یک برنامه‌ریز مبتنی بر قوانین ثابت، بدون هوش مصنوعی) برمی‌گردد؛ همین الگو برای Reasoning هم تکرار شده. این یعنی حتی اگر سرویس هوش مصنوعی کاملاً از کار بیفتد، پلتفرم هیچ‌وقت کاملاً متوقف نمی‌شود.

## استدلال و بازتاب (Reasoning / Reflection)

**تعریف ساده:** «Reasoning» یعنی یک LLM قبل از تصمیم‌گیری، مراحل فکری‌اش را (حتی به‌شکل خلاصه) بیان کند — نه فقط جواب نهایی. «Reflection» یعنی *بعد از* اجرای یک کار، سیستم به نتیجه نگاه کند و یک ارزیابی/توضیح تولید کند («این چقدر خوب پیش رفت؟»).

📍 **در این پروژه:** هر اجرای هدف، هم قبل از اجرا (`think()`) و هم بعد از آن (`reflect()`) یک `ReasoningTrace` واقعی تولید و ذخیره می‌کند — با این قید مهم و آگاهانه که این استدلال **فقط توضیحی است**، هیچ‌وقت خودش تصمیم نمی‌گیرد کدام قابلیت اجرا شود (سری اصلی، فایل ۱۴).

## سیستم چندعامله (Multi-Agent System) و تفویض کار (Delegation)

**تعریف ساده:** به‌جای یک Agent واحد که سعی می‌کند همه‌کاره باشد، چند «پرسونا»ی تخصصی (مثلاً یکی برای فروش، یکی برای پشتیبانی) وجود دارد، و یکی می‌تواند بخشی از کار را به دیگری «تفویض» (Delegate) کند.

**چرا مهم است:** یک پرسونای متخصص فروش، قوانین برنامه‌ریزی متفاوتی نسبت به یک پرسونای پشتیبانی دارد؛ تفویض یعنی هر بخش از کار به بهترین «متخصص» موجود سپرده شود.

📍 **در این پروژه:** یک نکته‌ی معماری جالب و صادقانه: پرسونا (مثل «مدیرعامل» یا «فروش») فقط یک **طبقه‌بندی برای برنامه‌ریزی** است، نه یک هویت مجزا با مجوزهای خودش — یعنی تفویض کار **هرگز** نمی‌تواند دسترسی جدیدی به کسی بدهد که از قبل نداشته (یک تصمیم امنیتی آگاهانه، سری اصلی فایل ۱۴).

## Hallucination (توهم مدل)

**تعریف ساده:** وقتی یک LLM با اطمینان کامل چیزی می‌گوید که واقعیت ندارد — مثلاً اسم یک تابع/قابلیتی که اصلاً وجود ندارد.

**چرا مهم است:** هیچ سیستم جدی نباید کورکورانه به خروجی یک LLM اعتماد کند؛ باید همیشه یک لایه‌ی اعتبارسنجی واقعی وجود داشته باشد.

📍 **در این پروژه:** اگر یک LLM اسم یک قابلیت ساختگی و ناموجود پیشنهاد بدهد، همان لحظه‌ی اجرا با یک خطای واقعی و مشخص (`CapabilityNotFoundException`) رد می‌شود — دقیقاً مثل هر ورودی نامعتبر دیگری، بدون هیچ اعتماد کورکورانه.
