# ۳. پشته‌ی فناوری و ساختار پروژه

## پشته‌ی فناوری

| لایه | فناوری |
|---|---|
| بک‌اند | Laravel 12، PHP 8.2+ |
| پایگاه‌داده | MySQL (در توسعه/تست: SQLite در حافظه) |
| کش و صف | Redis (پیش‌فرض توسعه: `database`)، Queue Workers |
| فرانت‌اند پنل مدیریت | Tailwind CSS v4 + Alpine.js + Chart.js، باندل‌شده با Vite |
| PDF | `barryvdh/laravel-dompdf` |
| HTTP کلاینت خارجی | Guzzle |
| سبک معماری | Modular Monolith، Domain-Driven Design، Clean Architecture، SOLID، Event-Driven، API-First |

نکته‌ی مهم درباره‌ی PHP: نسخه‌ی ۸.۲.۱۲ است، یعنی برخی امکانات PHP 8.3 (مثل ساخت آبجکت داخل مقدار ثابت کلاس) در دسترس نیست — این محدودیت کوچک، دلیل چند تصمیم فنی جزئی در کد است (فایل ۱۷ را ببینید).

## ساختار داخلی هر ماژول دامنه

همان‌طور که در فایل قبل گفتیم، هر ماژول این شکل را دارد (مثال واقعی از Commerce):

```
app/Modules/Commerce/
├── Domain/
│   ├── Entities/        Product, Category, Cart, CartItem, Inventory, Order, ...
│   ├── ValueObjects/     Money, SKU, ProductStatus, Quantity, ...
│   ├── Services/         PricingService, CouponValidationService, ...
│   ├── Events/           ProductWasCreated, OrderWasPlaced, ...
│   ├── Repositories/      ProductRepositoryInterface, OrderRepositoryInterface, ...
│   └── Exceptions/        ProductNotFoundException, ...
├── Application/
│   ├── Actions/           CreateProductAction, PlaceOrderAction, ...
│   ├── DTOs/               ProductData, OrderData, ...
│   ├── Jobs/                ProcessBulkImportJob, ...
│   └── Services/            ConnectorRegistry, PaymentGatewayInterface, ...
├── Infrastructure/
│   ├── Models/              مدل‌های Eloquent
│   ├── Repositories/         پیاده‌سازی Repository ها
│   └── Connectors/            اتصال‌دهنده‌های خارجی مثل WooCommerce
├── Interfaces/MCP/           تعریف قابلیت‌های MCP این ماژول
└── CommerceServiceProvider.php  ← اتصال همه‌چیز به کانتینر Laravel
```

الگوی هفت‌مرحله‌ای ساخت یک قابلیت جدید (که در تمام ماژول‌ها تکرار می‌شود):

```
Entity → Repository Interface → Eloquent Model + Repository →
DTO → Action → Domain Event → ثبت در ServiceProvider
```

## چگونه در کد پیش برویم؟ («نقشه‌ی راه» خواندن این آموزش)

فایل‌های ۴ تا ۱۶ این آموزش، دقیقاً به‌ترتیبی هستند که خود پروژه ساخته شده — یعنی همان ترتیب فازها:

| فاز | چه چیزی ساخته شد | فایل مرتبط در این آموزش |
|---|---|---|
| Phase 1 | هسته (Core) + دروازه MCP | فایل ۴ و ۵ |
| Phase 2 | ماژول Commerce (۶ مرحله) | فایل ۶ |
| Phase 3 | CRM، Finance، Workflows، Loyalty، Reporting | فایل ۷ |
| Phase 4 | Shipping، Notifications، i18n، پنل مدیریت، Analytics، نسخه‌بندی API، بهینه‌سازی عملکرد (۸ مرحله) | فایل ۸، ۹، ۱۰ |
| Phase 5 | تنوع محصول، انبار چندگانه، عملیات دسته‌ای، تخفیف پیشرفته، اشتراک (۵ مرحله) | فایل ۱۱ |
| Phase 6 | هوش مصنوعی عامل‌محور — Agent Orchestrator (۶ مرحله) | فایل ۱۲، ۱۳، ۱۴، ۱۵ |
| — | OpenRouter + دموی زنده Showcase | فایل ۱۵، ۱۶ |

این ترتیب مهم است، چون هر فاز روی مکانیزم‌های فاز قبل بنا شده — فهمیدن Commerce قبل از Agent Orchestrator ضروری است، چون عامل‌های هوشمند دقیقاً همان قابلیت‌های Commerce را با MCP صدا می‌زنند.
